# Approvals and Mandate theme audit

Mode: after (existing session choice). Scope: aligning Approvals and Mandate with the approved Chat theme while retaining the finance workflow.

No actionable findings remain. Both pages use the same Google Sans/Arial stack, centered 760 px content lane, pale panels, purple brand and rounded controls as Chat. Page descriptions, role context and real request counts replace the legacy technical eyebrow labels. Phone layouts reduce spacing and stack financial facts without clipping long identifiers.

Approvals preserves the actual request type, expiry, supplier, requester, role, amount, invoice facts, changes and warnings. Warnings keep semantic amber styling. Confirm/Decline remain distinct, disabled while processing and connected to the existing provider. Empty and connection/queue error states have real navigation or retries. No sample finance data is embedded in product components.

Mandate describes the existing draft/review process without adding a fictional policy editor. Only an actual owner receives the draft action. Loading and connection errors do not masquerade as permission restrictions. Draft success links to Approvals, and pending/error status reflects the actual queue.

Browser QA uses explicit test-only payment and mandate fixtures. It checks successful/failed decisions, processing locks, draft failure/success, owner restrictions, connection/queue retries, keyboard activation and viewport widths 1440/1024/768/390/320. Twelve browser-computed contrast checks pass, including the new button boundaries. Desktop, phone, empty and non-owner screenshots were reviewed. Full Chat regression also passed after the page changes. No real finance action or model call is made by these tests.

The backend, API shape and workspace provider are unchanged. Gate evidence is recorded in `frontend/DELIVERY-GATE.md` and generated `test-results/finance-results.json`.
