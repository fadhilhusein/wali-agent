Mode: after (session choice). Scope: follow-up to screenshots showing the composer obscured by mobile browser UI.

No actionable findings remain in the emulated scope. Mobile uses a fixed shell capped by 100svh, viewport percentage and measured available height. The calculation includes innerHeight, document clientHeight and VisualViewport, with a fallback when that API is absent. The viewport metadata requests content resizing for keyboards and enables safe-area insets; existing dock padding consumes the bottom safe area. Desktop layout is unchanged.

The mobile regression passes four viewport sizes, stale oversized measurements, scrolling to the final prompt, prompt tapping/focus, visible Send controls and shrinking/restoring the visual viewport while focused. Full Chat and profile suites pass with mocked APIs. These are Chrome emulation and controlled viewport tests, not a claim of physical Safari/Android toolbar or keyboard verification.
